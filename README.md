## 프로젝트 소개

「영원한 7일의 도시」는 서비스가 종료된 모바일 게임입니다. 원본 서버의 소스와 게임 데이터는 남아 있지 않고 클라이언트 앱만 남았습니다. 이 프로젝트는 2021년에 기록된 HTTP 캡처를 정답지로 삼아 서버 응답을 원본과 바이트 단위로 같게 만들고, 클라이언트 스크립트를 소스로 되살려 클라이언트가 읽는 규칙을 서버에 다시 구현합니다.

**주요 기능**

- **부팅과 로그인 복원**: 업데이트 확인, 서버 목록, 로그인, 게이트 서버 접속까지의 22단계 부팅 흐름을 재현합니다.
- **도시와 스토리**: 프롤로그, 도시 7일 반복, 엔딩과 다음 회차를 서버 규칙으로 다시 구현했습니다.
- **영웅 육성과 콘텐츠**: 영웅 육성과 장비 강화, 던전류 콘텐츠, 이벤트 활동을 계정별 상태와 함께 구현했습니다.
- **복원 도구**: 암호화된 클라이언트 스크립트를 읽을 수 있는 Python 소스로 되살리고, 소스에서 RPC 목록과 데이터 표를 뽑습니다.
- **앱 안 서버**: PC 서버 없이 기기만으로 실행하는 단독 구성을 만들었습니다.

에뮬레이터와 실기기(태블릿)에서 도시 화면 진입과 콘텐츠 실행을 확인했다는 기록이 작업 일지에 있습니다.

## 동작 구조

| 구성 요소 | 역할 | 주고받는 것 |
|---|---|---|
| 이름 해석과 중계 | 게임 도메인을 복원 서버로 돌리고, 접속 종류에 따라 나눈다 | DNS 질의, 80/443 접속 → HTTP 서비스 또는 게이트 서버 |
| HTTP 서비스 | 설정, 업데이트 확인, 로그인, 결제, 텔레메트리에 답한다 | HTTP 요청 → 2021 캡처와 같은 응답 |
| 게이트 서버 | 로그인 이후 게임 통신을 받는 원시 TCP 서버 | 길이 접두 protobuf 메시지 → 엔티티 생성, RPC 응답 |
| 아바타 계층과 RPC 핸들러 | 접속한 계정의 호출을 기능별 핸들러로 보낸다 | 호출 이름과 인자 → 응답, 상태 변경 |
| 게임 규칙 모듈 | 도시, 영웅 육성, 던전류, 이벤트 규칙 | 계정 상태와 표 데이터 → 바뀐 상태 |
| 상태 저장 | 계정당 파일에 진행 상태를 저장한다 | 상태 → 안전한 파일 교체 |
| 복원 도구 파이프라인 | 클라이언트 스크립트에서 소스, RPC 목록, 표를 만든다 | 클라이언트 리소스 → 소스, 목록, 표 |
| 검증 도구 | 캡처와 서버 응답을 대조하고 서버 호출을 클라이언트 스텁과 대조한다 | 캡처, 호출 → 같음·다름 판정 |
| 앱 안 서버 | 기기 안에서 서버를 별도 프로세스로 실행한다 | 앱 안 VPN이 돌려준 접속 → 서버 응답 |

### 부팅에서 도시 진입까지

1. 클라이언트가 게임 도메인을 질의하고 복원 서버 주소를 받습니다.
2. 업데이트 확인과 서버 목록 요청이 HTTP 서비스로 갑니다.
3. 로그인 응답을 받은 뒤 서버 목록이 알려 준 게이트 주소로 TCP 접속합니다.
4. 게이트 서버가 로그인 정보를 받은 뒤 그 계정의 아바타를 만들어 스냅샷과 함께 보냅니다.
5. 클라이언트가 도시 화면에 진입하고 5초 간격으로 생존 신호를 보냅니다.

### 규칙 복원 흐름

1. 클라이언트 스크립트를 복호화합니다.
2. 바이트코드를 재작성해 Python 소스로 되살립니다.
3. 소스에서 RPC 목록과 데이터 표를 뽑습니다.
4. 클라이언트가 읽는 필드와 순서를 계약 문서로 정리하고 서버 규칙을 구현합니다.
5. 가짜 클라이언트 테스트와 에뮬레이터 화면·로그로 확인합니다.

## 문제 해결 기록

### 문서는 완료인데 도시 진입이 0회였던 기준선

- **증상**: 문서가 한 단계를 완료로 적었지만, 에뮬레이터는 업데이트 확인 단계를 통과하지 못했습니다.
- **변경**: 9월 실험으로 바뀐 서버 응답을 2021 캡처 원본으로 되돌리고, DNS와 인증서 구성을 다시 만들었습니다.
- **재발 방지**: 응답 길이와 해시를 고정한 회귀 테스트와 캡처 대조 도구를 추가했습니다.
- **시기**: 2026.10 (커밋 기준)

### 로그인 실패 원인의 오진

- **증상**: 로그인에 실패해 게이트 서버 문제로 보였습니다.
- **변경**: 전 포트 패킷 캡처로 게이트 접속이 0건임을 확인했고, 실제 원인인 서버 목록 응답과 중계 설정을 고쳤습니다.
- **시기**: 2026.05 (분석 보고서 기준)

### 서버 호출의 잘못된 키로 화면이 멈춘 문제

- **증상**: 프롤로그 맵이 비고 클라이언트에 예외가 남았습니다.
- **변경**: 서버가 보내는 전투 데이터에 빠진 키를 채웠습니다.
- **재발 방지**: 가짜 클라이언트가 서버가 보내는 모든 호출을 복원된 클라이언트 스텁과 대조하는 검사를 테스트에 넣었습니다.
- **시기**: 2026.10 (분석 보고서 기준)

### 게임만 껐다 켜면 앱 안 서버에 접속하지 못한 문제

- **증상**: 게임 프로세스만 종료하고 다시 켜면 접속하지 못했습니다.
- **원인**: VPN 장치가 사라지면 안드로이드가 서버의 듣는 소켓을 닫았고, 기존 테스트는 항상 두 프로세스를 함께 종료해 이 경우를 다루지 못했습니다.
- **변경**: 닫힌 소켓을 서버가 스스로 다시 열고, 접속 화면이 단계적으로 복구하게 했습니다.
- **시기**: 2026.10 (분석 보고서 기준)

### 가설을 버리고 원인을 찾은 시간 초과

- **증상**: 분석 도구의 한 기능이 30초 시간 초과로 실패했습니다.
- **변경**: 처음 추정한 버전 조합 가설을 버리고, 최소 환경과 비교해 외부 조회 설정이 원인임을 찾아 2.1초로 줄였습니다.
- **시기**: 2026.10 (분석 보고서 기준)

## 품질과 운영

- **테스트**: 테스트 함수가 약 3,200개입니다 (정적 집계). 커밋 메시지에 적힌 통과 수는 2026.10.18 기준 3,848개입니다.
  - 서버 호출을 클라이언트 스텁과 대조하는 와이어 검사: 테스트 파일 100여 개가 사용합니다.
  - 2021 캡처 대조: 정적 응답의 길이와 해시를 고정합니다.
  - 원본 대조: 능력치 계산을 클라이언트 소스로 실행한 결과와 비교해 영웅 160명, 장비 492개에서 차이가 없었다고 분석 보고서에 기록되어 있습니다.
  - 서버 시계와 난수 시드를 고정해 결과가 재현되게 했습니다.
- **기기 구성 대조**: 같은 테스트를 기기 구성에서도 실행하고, 진짜 FastAPI와 응답 119건을 비교했습니다. 커밋 메시지 기준으로 같음 113, 알려진 차이 6, 문제 0입니다.
- **CI·배포**: CI 설정은 없고, 서버는 systemd 서비스와 nginx, dnsmasq로 운용합니다.
- **에러 처리와 로깅**: PC 서버는 로그를 파일로 영구 기록합니다. 앱 안 서버는 조각 파일, 총량 300MB 제한, 반복 줄이기, 비밀값 가리기를 적용합니다. 게이트 서버는 예외를 접속 단위로 가두고 중복 로그인을 정리합니다.
- **증거 게이트**: 서버 응답은 패킷 근거와 클라이언트 소스 근거를 모두 확인하고, 클라이언트 변경은 정당화 문서를 남기며, 완료 조건에 회귀 테스트 1개 이상을 넣었습니다.

## 한계와 개선 방향

- 원본 서버의 규칙이 없어 클라이언트에 없는 규칙 다수는 추론이며, 코드 주석이 근거 등급을 표기합니다.
- 정적 집계로 서버 호출 1,334개 중 약 48.5%에 핸들러나 의도적 무응답이 있습니다.
- 2021 캡처는 HTTP 로그인 구간뿐이라 게이트 구간에는 정답지가 없습니다.
- 전투 서버가 없어, 온라인 전투가 필요한 콘텐츠는 클라이언트가 스스로 전투를 계산하게 돌려보냅니다.
- 서버 시계 구간이 문서는 30주, 코드는 26주로 적혀 있는 등 갱신되지 않은 서술이 있습니다.
- 앱 안 서버는 64비트와 API 24 이상이 필요하고, VPN 허용이 필요하며, 다른 VPN과 함께 쓸 수 없습니다.

## 알고 보면 좋은 배경지식

- **게이트 서버**: 로그인 이후의 게임 통신을 받는 원시 TCP 서버입니다. HTTP 서비스가 알려 준 주소로 접속합니다.
- **엔티티와 스냅샷**: 서버와 클라이언트가 함께 들고 있는 객체(계정, 아바타)와, 로그인 때 한꺼번에 보내는 계정 상태입니다.
- **RPC 목록**: 클라이언트 소스에서 뽑은 호출 이름 목록입니다. 구현 범위의 기준이고, 테스트가 서버 호출을 이 목록과 대조합니다.
- **서버 시계**: 한정 이벤트를 다시 열기 위해 서비스 말기 구간을 되풀이하는 서버 쪽 날짜입니다.
